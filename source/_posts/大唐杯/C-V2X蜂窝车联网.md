C-V2X 是 **Cellular Vehicle-to-Everything**（蜂窝车联网）的缩写，是 3GPP 从 Release 14 开始制定的基于蜂窝通信的车联网技术标准。它让车辆能够与周围环境（其他车辆、行人、路侧设施、网络）进行低时延、高可靠的信息交换。

---

## 一、C-V2X 的核心概念

### 1. 四种通信场景（“X” 代表 Everything）

| 通信类型    | 说明              | 典型应用      |
| ------- | --------------- | --------- |
| **V2V** | 车与车             | 碰撞预警、变道辅助 |
| **V2I** | 车与基础设施（交通灯、RSU） | 绿波通行、限速提醒 |
| **V2P** | 车与行人（手机/穿戴设备）   | 行人横穿预警    |
| **V2N** | 车与网络（云/服务器）     | 导航更新、远程诊断 |

### 2. 两种工作模式

- **直连通信（PC5 接口 / Sidelink）**  
  不经过基站，车辆之间直接通信，使用 **5.9 GHz ITS 频段**（部分国家已分配）。支持 **广播、组播、单播**，低时延（<10ms），是主动安全的基石。

- **蜂窝通信（Uu 接口）**  
  通过基站和核心网通信，用于 V2N 场景，以及覆盖范围外的补充。

> 关键点：C-V2X 同时支持 **4G LTE-V2X**（R14/R15）和 **5G NR-V2X**（R16+），后者支持更灵活的通信方式（单播/组播）和更高的可靠性（99.999%）、更低时延（3~5ms）。

---

## 二、C-V2X 与 DSRC（IEEE 802.11p）的主要区别

| 对比项 | C-V2X | DSRC |
|-------|-------|------|
| 底层技术 | 4G/5G 蜂窝 | Wi-Fi 变体（802.11p） |
| 同步方式 | 依赖 GNSS 或 eNB 同步 | 自同步（竞争机制） |
| 覆盖范围 | 更大（蜂窝+直连） | 较小（约300-500米） |
| 演进路线 | 与 5G 融合，支持高阶V2X | 较慢，缺少NR演进 |
| 产业链 | 主流（3GPP、5GAA 推动） | 部分地区（美国早期） |

目前全球趋势更偏向 C-V2X（中国、欧洲明确支持，美国也开始转向）。

## 三、复习 C-V2X 知识点的建议

根据考试或面试常见考点，推荐以下**复习框架**：

### 1. 掌握基础概念
- 四种通信场景（V2V/V2I/V2P/V2N）
- 两种接口：PC5（直连） vs Uu（蜂窝）
- 两种模式：Mode 3（基站调度） vs Mode 4（UE自主选资源）—— LTE-V2X 时的重要区分

### 2. 重点理解 5G NR-V2X 的新特性（R16/R17）
- 支持 **单播和组播**（以前只有广播）
- **HARQ 反馈**（提高可靠性）
- **CSI 测量**（自适应调整）
- **资源抢占机制**（高优先级业务）
- **更低的时延**（<5ms）和更高的可靠性（99.999%）

### 3. 熟悉关键参数和频段
- 频段：5.905-5.925 GHz（ITS 频段），部分国家用 5.9 GHz 或 5.8 GHz
- 同步源：GNSS 或基站
- 通信距离：直连可达数百米（视距条件）

### 4. 对比记忆（DSRC / LTE-V2X / NR-V2X）
建议画一个表格，列出各版本支持的功能：
- 是否支持单播/组播
- 是否支持 HARQ
- 时延/可靠性指标
- 资源分配方式

### 5. 理解典型应用分层
- **基础安全**（Day 1）：紧急刹车、交叉路口碰撞预警 → LTE-V2X 已支持
- **高级自动驾驶**（Day 2+）：协同变道、传感器共享、远程驾驶 → 需要 NR-V2X

### 6. 关注协议栈
- PC5 接口的协议栈：物理层（SL）、MAC、RLC、PDCP、RRC（部分）
- 了解 **Sidelink** 信道：PSCCH（控制）、PSSCH（数据）、PSBCH（广播）、PSFCH（反馈——NR 新增）

### 7. 刷题与查漏
- 常见考题形式：判断通信类型、选择正确接口、对比 DSRC、指出 NR-V2X 新功能
- 推荐资料：3GPP TR 22.886（场景需求）、TS 23.287（架构）、TS 38.885（PC5 物理层）
